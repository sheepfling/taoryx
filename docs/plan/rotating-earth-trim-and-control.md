# Rotating-Earth Trim And Control

## Objective

Make Earth rotation a common kinematics and controller concern rather than a
vehicle-specific source of duplicated trims. Vehicle trim variables remain
local and atmosphere-relative. A shared operating-point context maps them into
ECIC state, applies Earth transport, and records the location and Earth model
used by the trim and controller artifact.

## Design

`EarthRotationAdapter` remains the frame boundary between ECIC integration and
ECFC atmosphere/aerodynamics. `EarthOperatingPoint` adds the reusable location
and transport context for trim and controller adapters:

```text
local trim velocity + geodetic location
    -> ECFC Earth-relative velocity
    -> ECIC inertial velocity (+ omega x r)
    -> atmosphere / propulsion / aerodynamics
```

Controllers should consume air-relative velocity and local-frame references.
Earth-rate attitude transport and navigation feed-forward belong in the common
frame layer, not in vehicle-specific gain tables.

The zero-rate B747, X8, and Hummingbird cases remain source-parity baselines.
The X-15 source case already declares nominal Earth rotation. Representative
rotating-Earth reports are generated by:

```text
python tools/regenerate_rotating_earth_trims.py
```

The command records the Earth rate, solver path, output hashes, and success
status in `artifacts/golden_plants/rotating_earth/manifest.json`. It supports
selective regeneration with repeated `--vehicle` arguments and alternate
Earth rates with `--earth-omega`. It also records a default -60, -30, 0, 30,
and 60 degree latitude screen; customize it with repeated `--latitude-deg`
arguments and set the declared gravity reuse threshold with
`--gravity-tolerance-fraction`.

## Latitude Policy

The canonical trim is not duplicated for every latitude. A local operating
point is transported analytically using the latitude-dependent Earth-fixed
position and `omega x r`. Latitude continuation or sensitivity checks are
used only when effective gravity, wind, atmosphere, or table validity changes
the local equilibrium beyond the declared tolerance.

## Exit Conditions

- `EarthOperatingPoint` converts local ECFC conditions to correct ECIC
  transport and preserves explicit frame/unit metadata.
- Propulsion and aerodynamic tables consume air-relative speed under rotating
  Earth, not inertial transport speed.
- B747, Skywalker X8, Hummingbird, and X-15 representative rotating-Earth
  trim reports converge through one regeneration command.
- Controller realization metadata carries the trim operating point.
- ECIC controller telemetry can be adapted to the same local channels through
  `EarthRelativeVelocityStateAdapter` without duplicating gains by latitude.
- Zero-rate source-parity cases remain labeled and unchanged.
- Latitude continuation reports whether one local trim remains valid or a
  correction is required.
